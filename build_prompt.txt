SortPi Landing Page: Antigravity Build Prompt

Prepared 27 October 2026. Use this to build the new https://www.sortpi.com landing page in Google Antigravity. It assumes the visual design comes from Stitch (see the Stitch prompt doc) and that Antigravity turns it into working code.

1. How to use this document

Step 1: create an empty project folder and open it in Antigravity. If you are replacing the existing SortPi site, open that repo instead.

Step 2: put the Stitch outputs (screenshots or exports of the desktop and mobile designs) in a /design folder inside the project.

Step 3: paste the master build prompt (section 2) into the agent. Ask it to produce its plan first and read the plan before you approve it.

Step 4: put the content from section 3 into the project as the content files the prompt describes, or paste section 3 below the prompt.

Step 5: after the first build, run the follow-up prompts in section 4 one at a time.

Step 6: check the result against section 5 before anything goes live.

If you use workspace rules in Antigravity, save the "Working rules" block from the master prompt as a rule file so every task follows it.

4. Follow-up prompts (run one at a time after the first build)

4.1 Responsive pass

Test every section at 360px, 390px, 768px, 1024px and 1440px. Fix overflow, cramped spacing, text that wraps badly, tap targets under 44px and any horizontal scrolling. Make sure each text block is rendered once and not duplicated for desktop and mobile. Show before and after screenshots for anything you change.

4.2 Performance pass

Run Lighthouse (mobile, throttled) and list the top issues. Fix them in this order: LCP image, layout shift, unused JavaScript, image sizes and formats, font loading. Report the scores before and after. Do not remove features to improve the score without asking.

4.3 SEO and structured data pass

Check the title, description, canonical, Open Graph and Twitter tags, heading order, alt text, sitemap, robots and JSON-LD (Organization, SoftwareApplication, FAQPage). Validate the JSON-LD and fix errors. Confirm there is one H1 and that no heading or paragraph appears twice in the rendered HTML.

4.3b Bangla pass

Review the Bangla version of every section. Check that fonts render correctly, nothing overflows, line height suits Bangla script, numbers and taka symbols display correctly and the language switch updates the html lang attribute. List every Bangla string still marked 'needs human review'.

4.4 Accessibility pass

Audit with an automated checker and then manually with the keyboard only. Check focus order, visible focus, modal focus trapping, carousel controls, accordion behavior, form labels and error messages, color contrast and reduced-motion behavior. Fix every issue and list what you changed.

4.5 Release readiness

Run the production build with ALLOW_PLACEHOLDERS unset and report every remaining placeholder. Confirm .env.example is complete, no secrets are committed, all links work (no '#' links remain), the 404 page exists, redirects from the non-canonical domain are documented, and the README explains how to deploy. Give me a go or no-go list.
